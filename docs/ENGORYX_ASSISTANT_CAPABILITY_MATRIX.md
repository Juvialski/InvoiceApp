# Engoryx Assistant Capability Matrix

Status: Wave 3 baseline audit at `1950e489b184a2c298b27db1d6ab4ff1c21ec5f0` (2026-08-30). This is the durable coverage tracker for Core Hardening Wave 3. `COMPLETE` means the current Assistant path is available and tested at the capability boundary shown. `PARTIAL` means only the listed capabilities are present. `INTENTIONAL UNSUPPORTED` means the current product or security boundary does not expose a safe Assistant operation. `DEFERRED` is reserved for frozen or future product scope.

The inventory was built from the current routes and deterministic UI components, `src/features/registry.ts`, `src/utils/accessControl.ts`, canonical domain libraries and RPC-backed persistence, `scripts/workflow-map/graph.ts`, the Assistant registry/executors, and the focused Assistant/domain tests. UUIDs in this document identify implementation contracts only; normal Assistant prose must use human labels.

## Capability columns

The compact notation below is used in the matrix:

- `R` = read/query and question answering from persisted source data.
- `N` = allowlisted navigation/deep link after company-bound entity resolution.
- `C` = create preparation → explicit confirmation → guarded execution.
- `E` = edit/correct preparation → explicit confirmation → guarded execution.
- `L` = remove/lifecycle preparation → explicit confirmation → guarded execution.
- `X` = restore/reactivate preparation → explicit confirmation → guarded execution.
- `P` = prepare/preview contract; `H` = human confirmation; `G` = guarded execution.
- `—` = not applicable to that workflow.

Every `C`, `E`, `L`, and `X` capability is required to use the same effective permission, lifecycle validation, RLS/RPC boundary, and audit/history rule as the deterministic UI. `INTENTIONAL UNSUPPORTED` entries must remain explicit and must not be advertised as executable.

## Wave 3 completion ledger

The baseline gaps above are converted to completion statuses during implementation. No row may remain `PARTIAL` or `GAP` without one of these dispositions:

| Disposition | Meaning | Evidence required |
| --- | --- | --- |
| `COMPLETE` | Assistant capability is implemented with deterministic prepare/confirm/execute or bounded read/navigation parity. | Focused tests, changed-surface review, and applicable full validation. |
| `INTENTIONAL UNSUPPORTED` | A safe Assistant path is not exposed because the current product lacks a canonical operation or the action requires a specialized UI/binary/provider boundary. | Matrix reason, user-facing refusal/help text, and a negative test proving it is not advertised or executable. |
| `DEFERRED` | Frozen/future product scope only, such as Scheduling/Gantt/CPM or roadmap modules. | Matrix reason and feature-registry/doc evidence. |

Wave 3 must also remove user-visible legacy `InvoiceApp` wording from Assistant prompts, tool descriptions, help/tour labels, fallback/errors, and response fixtures. Internal repository names, migration names, and test infrastructure names are not themselves user-visible scope.
