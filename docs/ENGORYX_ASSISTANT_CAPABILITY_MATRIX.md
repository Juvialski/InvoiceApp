# Engoryx Assistant Capability Matrix

Status: Wave 3 current-state coverage, updated 2026-08-30. This is the durable definition-of-done tracker for Full Assistant Parity. Each row is classified as `COMPLETE`, `INTENTIONAL UNSUPPORTED`, or `DEFERRED`; there are no unexplained partial rows. A check in Read/query or Question answering means persisted company data can be used safely. `P → H → G` means deterministic prepare, explicit human confirmation, and guarded execution. Navigation is resolved against the authenticated deployment company before a client deep link is emitted.

The inventory was checked against current routes/components, `src/features/registry.ts`, `src/utils/accessControl.ts`, domain libraries, persistence/RPC boundaries, `scripts/workflow-map/graph.ts`, Assistant adapters, and focused tests. ## Completion ledger

- `COMPLETE`: implemented and bounded at the listed capability boundary; mutation rows use deterministic preparation, explicit confirmation, guarded execution, and refreshed result handling where applicable.
- `INTENTIONAL UNSUPPORTED`: not advertised as executable because the current product has no canonical Assistant-safe operation or because a specialized human/binary/provider/export boundary is required. The reason is recorded in the final column and the negative boundary is covered by registry/security tests.
- `DEFERRED`: frozen or future product scope only.

Wave 3 cross-cutting evidence is maintained in the Assistant registry, `assistantParityWave3.test.ts`, route/action policy tests, attachment/prompt tests, and workflow-map source/derived-output checks. User-visible Assistant text uses `Engoryx`; internal repository, migration, and test-infrastructure names are not product response text.
