## Scope and existing implementation

The production enabled adapter set in `src/app/routes/OperationsWorkbookRoute.tsx` is Projects, Cost Codes, direct Expenses, RFQs and Purchase Orders. `src/lib/operationsWorkbookModel.ts` already describes Supplier Invoices, Vendors, Materials, Equipment, Warehouse and Payroll as `future-adapter`; declarations are not operational adapters. Do not turn readiness flags on before data loading, delegated persistence, authorization, protected fields, conflicts and tests exist.

Reuse `WorksheetEditor`, `operationsWorkbookModel.ts`, `operationsWorkbook.ts`, `combinedOperationsWorkbook.ts` and `OperationsWorkbookTransfer.tsx`. Existing domain XLSX implementations are `projectsWorkbook.ts`, `expensesWorkbook.ts` (including read-only Supplier Payables), and `procurementWorkbook.ts`. Suppliers, inventory and payroll remain canonical domain data, not workbook-owned copies.

## Backward-compatible XLSX design

- Existing standalone Projects, Expenses and Procurement workbook kinds, headers, version and hidden `_HydroQualiSense` metadata retain their behavior. Existing five in-app sheets and the supporting exported child/read-only sheets must still round-trip.
- Keep combined version-1 import/export accepted without schema reinterpretation. Introduce a separately versioned expanded combined contract only when new sheets are enabled; route parsing explicitly by workbook kind/version. Do not make old files appear malformed because they omit newly optional sheets.
- New sheets carry stable canonical record IDs, domain/owner IDs, current company-bound snapshot fingerprints and authoritative expected versions where available. Metadata is comparison evidence, never an access credential. Protect all identities/parents/history/source/derived/lifecycle fields.
- Permission-filter both export and import review. Do not export payroll detail through project-summary access. A permission or company switch invalidates staged proposals; refresh permissions and source state immediately before Apply.
- Unchanged read-only sheets are permitted context. Edits to protected/read-only values produce explicit blocked-review errors and no mutation, not silent acceptance. Extra/new/missing rows never silently create or delete records.
- Reuse parser limits and formula/macro/external-link/unsafe-cell protections, duplicate-ID and cross-company checks. Unknown future kinds/versions/sheets fail with an actionable message.
- Review and Apply remain domain-scoped; preserve per-owner partial-failure/retry evidence. Do not invent an all-sheets transaction or retry completed proposals without refreshing canonical state. No new financial truth is stored by the workbook.
